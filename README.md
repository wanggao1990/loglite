# loglite

**English** | [简体中文](README_zh.md)

A dependency-free C++17 asynchronous logging library with a clean frontend/backend separation.

- **Frontend**: `LOGLITE_LOG*` macros format the message and the complete line on the caller thread, then perform one very short enqueue.
- **Backend**: a single writer thread drains the queue in FIFO order and dispatches every record to all `Sink`s; file, console, callback and custom backends are pluggable at runtime.
- **Ordering**: the global sequence number `seq` is allocated inside the enqueue critical section, and a single consumer writes in FIFO order — records from the same thread are always written in call order, and global order is strict (`seq` is internal and never printed).
- **Batched flushing**: file sinks flush after 64 KiB, the writer flushes all sinks every 200 ms, and `flush()` / `shutdown()` force a complete flush.
- **Timestamps**: microseconds (`epoch_us`, text `HH:MM:SS.ffffff`, JSON `ts` is a microsecond epoch).
- The library carries no project-specific prefix; projects add their own prefix through macros.

## Build

Requires CMake >= 3.15 and a C++17 compiler (VS2022 / v143 on Windows).

```powershell
cd 3rdparty/loglite
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Debug
cmake --build build --config Release
```

Generated projects and artifacts:

| Item | Path |
|---|---|
| Solution / projects | `build/loglite.sln`, `build/*.vcxproj` |
| Static library | `build/lib/<Config>/loglite.lib` |
| Executables | `build/bin/<Config>/loglite_tests.exe`, `loglite_sample.exe`, `loglite_bench.exe` |

CMake options:

| Option | Default | Description |
|---|---|---|
| `LOGLITE_BUILD_SHARED` | `OFF` | Build a DLL when `ON` (defines `LOGLITE_BUILD_SHARED` / `LOGLITE_USE_SHARED`) |
| `LOGLITE_BUILD_TESTS` | `ON` | Build the test suite and register it with ctest |
| `LOGLITE_BUILD_SAMPLE` | `ON` | Build the sample and register it as a ctest smoke test |
| `LOGLITE_BUILD_BENCH` | `ON` | Build the throughput benchmark (manual, not in ctest) |

Run:

```powershell
ctest --test-dir build -C Release --output-on-failure
.\build\bin\Release\loglite_sample.exe

```

To integrate elsewhere: add `include/` to the include path and link `loglite.lib`, or use CMake `add_subdirectory` followed by `target_link_libraries(app PRIVATE loglite)`.

## Quick start

```cpp
#include <loglite/loglite.h>
#include <cstdio>

int main() {
    loglite::initialize();                       // starts the writer lazily; optional
    loglite::reset_sinks();                      // remove the default console sink
    loglite::set_level(loglite::Level::trace);
    loglite::add_file_sink_utf8("app.log");      // defaults: 4 MiB rotation, 3 backups

    LOGLITE_LOG_INFO("start, image %dx%d", 512, 512);
    LOGLITE_LOG_WARN("score=%.2f", 12.34);
    LOGLITE_LOG_ERROR("failed: %s", "timeout");

    loglite::flush();        // wait until the queue is drained and all sinks are flushed
    loglite::shutdown();     // drain + flush + join before exit (required)
    return 0;
}
```

### Zero-initialization behavior

```cpp
#include <loglite/loglite.h>
int main() {
    LOGLITE_LOG_INFO("hello");
    return 0;                // visibility is NOT guaranteed
}
```

The default level is `info`, so the record is enqueued; the default sink on Windows writes to both the debugger (`OutputDebugStringA`) and `stdout`. Writing is **asynchronous**, however: the writer thread may not be scheduled before the process exits, and the default 200 ms timer has not fired yet. The library deliberately does not register an `atexit` hook — during DLL unload the loader lock is held and joining a thread would deadlock.

**To guarantee visibility and no lost tail records, call `flush()` and `shutdown()` explicitly:**

```cpp
LOGLITE_LOG_INFO("hello");
loglite::flush();
loglite::shutdown();
```

## Default policy

| Item | Default | How to change |
|---|---|---|
| Runtime level | `info` (2); `trace`/`debug` filtered out | `set_level()` / `loglite_set_level()`; `off` disables everything |
| Compile-time gate | Release (`NDEBUG`) = 2, Debug = 0 | `LOGLITE_COMPILE_LEVEL`, eliminated by `if constexpr` |
| Format | `text` | `set_format(Format::json)` |
| Timestamp | microseconds | fixed |
| `seq` | internal field, **not printed** | available to custom sinks for order checks |
| Default sink | one `ConsoleSink`: Windows = `OutputDebugStringA` + `stdout` + `fflush`, others = `stderr` + `fflush` | `reset_sinks()` then add your own |
| Callback | none | `set_callback()` |
| File sink | **not created by default** | `add_file_sink_utf8()`, defaults to 4 MiB x 3 rotation |
| Queue capacity | `0` = unbounded, no drops | `set_queue_capacity(n)`; drops the newest when full, counted by `dropped_count()` |
| File flush threshold | 64 KiB | `set_flush_policy(bytes, ms)`; `bytes=0` restores a flush per line |
| Timer flush | 200 ms | `interval_ms=0` disables the timer |
| Forced flush | `flush()` / `shutdown()` always flush completely | — |
| Writer thread | started lazily (first `submit()` or `initialize()`), **single thread** | `shutdown()` drains, flushes and joins |
| Short `LOG_*` macros | disabled | define `LOGLITE_ENABLE_SHORT_MACROS` |

## API reference

### Lifecycle

| Function | Description |
|---|---|
| `void initialize() noexcept` | Re-enable logging and ensure the writer is running |
| `void shutdown() noexcept` | Stop, drain, flush all sinks, join the writer, clear sinks (idempotent) |
| `bool is_shutdown() noexcept` | Whether logging is stopped |

After `shutdown()`, `submit()` is discarded by `enabled()`; call `initialize()` to resume.

### Configuration (all thread-safe)

```cpp
void   set_level(Level) noexcept;   Level   get_level() noexcept;
bool   enabled(Level) noexcept;
void   set_format(Format) noexcept; Format  get_format() noexcept;
void   reset_sinks() noexcept;      size_t  sink_count() noexcept;
void   add_console_sink() noexcept;
void   add_file_sink_utf8(std::string_view utf8_path,
                          std::uint64_t max_bytes = 4ull << 20,
                          int max_files = 3) noexcept;
void   add_sink(Sink*, bool take_ownership = true) noexcept;
void   set_callback(LogCallback, void* ctx) noexcept;
```

`LogCallback = void (*)(int level, const char* line, void* ctx)`, called serially on the writer thread. Logging from inside a callback is safe: that record is tagged `suppress_callback` so it cannot recursively trigger the callback.

### Async queue and flush policy

```cpp
void          flush() noexcept;                 // wait until all submitted records are written and flushed
std::size_t   queue_size() noexcept;
std::uint64_t dropped_count() noexcept;
void          set_queue_capacity(std::size_t) noexcept;
void          set_flush_policy(std::size_t bytes, unsigned interval_ms) noexcept;
std::size_t   flush_threshold() noexcept;
unsigned      flush_interval_ms() noexcept;
```

### `Record` and `Sink`

```cpp
struct Record {
    std::uint64_t    seq;        // global submission order (internal, not printed)
    Level            level;
    std::uint64_t    epoch_us;   // microseconds since Unix epoch
    std::uint32_t    thread_id;
    std::string_view file;
    int              line;
    std::string_view message;    // UTF-8
};

class Sink {
public:
    virtual ~Sink() = default;
    // formatted_line is a complete line (ends with '\n'), called in order by
    // the single writer thread
    virtual void write(const Record&, std::string_view formatted_line) = 0;
    // invoked on timer ticks, flush() and shutdown() to push buffers to the OS
    virtual void flush() {}
};
```

Custom backend:

```cpp
class ErrorCounter final : public loglite::Sink {
public:
    std::atomic<int> errors{0};
    void write(const loglite::Record& r, std::string_view) override {
        if (r.level == loglite::Level::error) errors.fetch_add(1);
    }
};

ErrorCounter counter;
loglite::add_sink(&counter, false);   // false = caller retains ownership
```

### Macros

```cpp
LOGLITE_LOG(level, ...)               // generic entry point
LOGLITE_LOG_TRACE/DEBUG/INFO/WARN/ERROR(...)
LOG_TRACE/DEBUG/INFO/WARN/ERROR(...)  // requires LOGLITE_ENABLE_SHORT_MACROS; each is #ifndef-guarded
```

Levels discarded by `LOGLITE_COMPILE_LEVEL` have their arguments **never evaluated** (`if constexpr`).

### C API

`loglite_initialize`, `loglite_shutdown`, `loglite_set_level`, `loglite_set_format`, `loglite_reset_sinks`, `loglite_add_console`, `loglite_add_file_utf8`, `loglite_flush`, `loglite_dropped_count`, `loglite_set_queue_capacity`, `loglite_queue_size`, `loglite_set_flush_policy`. All are `extern "C"` for FFI / cross-module use.

### Project-side prefix

`prefix.h` provides `LOGLITE_EXPAND`, `LOGLITE_PREFIXED(prefix, name)` and `LOGLITE_LEVEL_LIST(X)`:

```cpp
#include <loglite/loglite.h>
#include <loglite/prefix.h>

#define APP_LOG(...)       LOGLITE_EXPAND(LOGLITE_LOG(__VA_ARGS__))
#define APP_LOG_INFO(...)  LOGLITE_LOG_INFO(__VA_ARGS__)
#define APP_LOG_WARN(...)  LOGLITE_LOG_WARN(__VA_ARGS__)
namespace LOGLITE_PREFIXED(APP, log) = loglite;   // -> APP_log
```

`LOGLITE_EXPAND` is the extra expansion layer required by MSVC's legacy preprocessor when forwarding variadic arguments; the project also enables `/Zc:preprocessor`.

## Ordering guarantees

- Program order within a thread is preserved: consecutive `submit()` calls enqueue under the same queue lock. Other threads may interleave between two records, but never reorder them.
- `seq` allocation and `deque::push_back` happen in the same critical section, so `seq` equals the queue position. A single writer takes the whole queue via `batch.swap` in FIFO order and walks all sinks in that order.
- Every sink sees the same order; after `flush()` returns, all previously submitted records have been written and flushed.
- Fixed race: a submit that passed `enabled()` but acquired the queue lock after `shutdown()` is explicitly dropped by the in-lock `s.stop` check, so it cannot be stranded in the queue.

Scenarios that may **lose** records but never reorder them:

| Scenario | Effect |
|---|---|
| `set_queue_capacity(n)` with a full queue | Drops the newest; remaining records stay ordered. Unbounded by default |
| Concurrent `set_level()` / `shutdown()` | Some records filtered out by `enabled()` |
| System clock steps back | Timestamps may be non-monotonic; write order is unchanged |
| Logging from inside a callback | Goes to the next batch; other records may be interleaved |
| Crash before `flush()` | Tail buffers are lost |

## Lifecycle and DLL usage (important)

| Scenario | Consequence of not calling `shutdown()` |
|---|---|
| EXE exits normally | Usually not fatal: `State` is an intentionally leaked heap object, so its `std::thread` is never destroyed and a joinable-thread `std::terminate` is avoided; however **tail records are lost** and a line can be truncated |
| DLL `FreeLibrary` | **Fatal**: the OS does not terminate threads created by a DLL. After unload the writer executes unmapped code / touches an unloaded vtable -> `0xC0000005` (delayed by up to one 200 ms tick) |

- The host must call an exported shutdown function (forwarding to `loglite_shutdown()`) **before** `FreeLibrary`; EXEs call it at the end of `main()`.
- **Never** call `shutdown()` from `DllMain(DLL_PROCESS_DETACH)`: joining threads / doing I/O under the loader lock deadlocks.
- `set_flush_policy(0, 0)` (flush per line) only reduces log loss; it does **not** fix the DLL unload crash.

## Performance and known limitations

- All sinks are called serially by a **single writer**: any slow sink (Windows console / redirected pipe / `OutputDebugStringA` with a debugger attached) stalls every sink, including file sinks (head-of-line blocking). File contents remain ordered and complete, just written later.
- The default Windows `ConsoleSink` calls `fflush(stdout)` per line; GUI or console-less hosts should `reset_sinks()` and attach only a file sink.
- With the default unbounded queue, a persistently slow sink grows memory; use `set_queue_capacity(n)` to bound it at the cost of dropping the newest records (observable via `dropped_count()`).
- Producers still need one short `q_mtx` critical section (seq allocation + push) — the price of strict global ordering. There is no thread-local buffering yet.
- Single-process only; no cross-process synchronization, and `flush()` does not guarantee a physical fsync.

## Benchmark

Environment: Windows, VS2022 v143 (MSVC 19.38), x64 **Release**, generated by CMake, `build/bin/Release/loglite_bench.exe 1` (1 MiB payload per repeat, 3 repeats averaged).

Methodology:

- `submit`: `sink=none`, times only the producer loop (`vsnprintf` + full line formatting + enqueue), excluding writer wait.
- `e2e`: `sink=file`, times the producer plus `flush()` (writer drained and data on disk).
- These are two different configurations and must not be subtracted from each other.
- `1023 / 1024 / 1025 B` straddle the 1 KiB stack formatting buffer in the implementation.

### Historical comparison with the old "flush per line" implementation

Same machine, same parameters (1 MiB per repeat), `e2e` improvement:

| size(B) | old msg/s | new msg/s | ratio |
|---:|---:|---:|---:|
| 32 | 196,416 | 1,170,491 | ~5.96x |
| 128 | 192,840 | 970,827 | ~5.03x |
| 4096 | 84,157 | 121,920 | ~1.45x |
| 65536 | 24,290 | 28,571 | ~1.18x |

Optimizations: full-line formatting moved out of the enqueue lock, 64 KiB batched file flushing, and a 200 ms writer timer; `flush()` / `shutdown()` still force a complete flush.

### Interpretation

- Small messages are dominated by per-record overhead: high msg/s but low MiB/s. Large messages are bounded by memory copies and per-line I/O: msg/s drops while MiB/s rises.
- Throughput is flat or slightly lower from 1 to 8 producer threads: the bottleneck is the single writer plus per-line `fwrite`/flush and the `q_mtx` enqueue serialization; adding producers does not scale linearly.
- Further gains require thread-local buffers (less enqueue contention) or per-sink independent channels (remove head-of-line blocking). Both change the current strict global ordering semantics and need to be weighed carefully.
